# UWB 跟随、随机漫游与环绕：部署说明

核对日期：2026-10-11。源码在 `robotics/ros2/src/go2_uwb_behavior`，完整接口见 [UPSTREAM_API.md](UPSTREAM_API.md)。本说明不把旧设备的 CPU/帧率、底盘脚本或工作空间路径当作本板已验收结果。

## 1. 分工与前提

| 组件 | 职责 |
| --- | --- |
| 上层任务/语音适配 | 调用 3 个 Action 和 1 个 Service，保存 Goal Handle并协调速度控制权 |
| 统一行为链 | UWB 名义速度、双目按需计算、局部 MPPI、输入门控、围栏与停车流程 |
| 外部传感器 | RealSense 校正双目/CameraInfo、厂家 UWB 消息 |
| 外部底盘层 | 发布 /leg_odom2、TF；接收 /cmd_vel；管理遥控/程序控制模式 |

本包不启动底盘 SDK、RealSense 或 UWB 串口驱动。底盘桥接的模式切换和 idle_timeout 是外部部署策略，不是本包保证。

## 2. 构建与启动

按 [公共构建说明](../../../README.md) 构建 `uwb_aoa_pkg`、`go2_uwb_local_follow`、`go2_uwb_behavior`。每个板端终端加载相同的 ROS、依赖与安装前缀，例如构建完成后：

```bash
source /opt/ros/humble/setup.bash
source /home/marsdog/MarsDogPlatform/out/rk3588-rtabmap/use-rtabmap.sh
source /home/marsdog/MarsDogPlatform/out/rk3588-robotics/install/local_setup.bash
```

然后分别准备外部底盘、RealSense 和 UWB 驱动，核对：

```bash
ros2 topic type /leg_odom2
ros2 topic hz /libAoa_robot_publisher
ros2 topic hz /camera/camera/infra1/image_rect_raw
ros2 topic hz /camera/camera/infra2/image_rect_raw
ros2 run tf2_ros tf2_echo base_footprint camera_infra1_optical_frame
```

图像须是校正双目，与 CameraInfo 分辨率和基线一致。RealSense 的 IR、曝光、投射器设置按实际驱动与标定核对；旧的 `~/bin/rs-emitter` 不是本仓库必需脚本。合法空障碍点云不等于感知失败，应结合新鲜度、有效深度样本与诊断判断。

先启动禁止本节点运动的统一入口：

```bash
ros2 launch go2_uwb_behavior behavior_follow_roam.launch.py \
  enable_motion:=false cmd_vel_topic:=/cmd_vel
```

统一入口启动六个组件：行为控制器、UWB 适配器、disparity、障碍投影、滚动地图、局部速度规划器。**默认 enable_motion=true**；静态检查应显式 false。false 只约束本链路输出，不能阻止别的控制源。

不要额外启动旧 `local_follow.launch.py`、单独跟随节点或另一个直连 `/cmd_vel` 的规划器。确认控制权和测试场地后，才在新的启动命令中显式使用 `enable_motion:=true`。

## 3. 上层调用

```bash
ros2 action send_goal /go2/follow_uwb \
  go2_uwb_behavior/action/FollowUwb "{timeout_sec: 0.0}" --feedback

ros2 action send_goal /go2/random_roam \
  go2_uwb_behavior/action/RandomRoam \
  "{random_seed: 0, timeout_sec: 30.0, min_radius: 0.5, max_radius: 2.0}" --feedback

ros2 action send_goal /go2/orbit_uwb_once \
  go2_uwb_behavior/action/OrbitUwbOnce \
  "{timeout_sec: 60.0, orbit_radius: 1.0, direction: 0}" --feedback
```

这些是三个独立示例，不能同时发起。已有任务时新 Goal 被拒绝；上层先 cancel、等待终态，再按结果和底盘状态安排后续任务。Python Goal/cancel 模式见 [环绕客户端示例](OrbitUwbOnce上层调用说明.md)，其他 Action 使用同样的异步生命周期。

随机漫游的目标与围栏基于调用时冻结中心，不保证结束时跟随到主人后来的位置。环绕反馈到达约一周仍需等待成功 Result。Result/Feedback 是数字枚举，不是字符串。

## 4. 速度输出、门控与时限

| 项目 | 当前 YAML 配置/实现 |
| --- | --- |
| 控制循环 | 20 Hz；活动 Action 持续输出门控速度 |
| 空闲发布 | publish_idle_velocity=false；空闲静默，非零→零边沿补发零 |
| UWB 新鲜度 | 0.50 秒，按任务模式检查 |
| odom 新鲜度 | 0.20 秒 |
| 障碍新鲜度 | 0.70 秒 |
| 规划器命令新鲜度 | 0.20 秒 |
| 就绪窗口 | 2 秒 |
| 输入恢复窗口 | 3 秒 |
| 停车确认 | 新鲜 odom；低 twist 或稳定 pose，持续 0.30 秒；等待上限 2 秒 |

控制器虽然空闲静默，仍会显示为 `/cmd_vel` publisher。ROS 图上的发布者数量不能单独证明控制权；应核对正在发送的来源。Nav2/动作执行/遥控和 UWB 活动任务间的控制权由部署层负责，本包没有通用速度仲裁器或 Nav2 自动互锁。

Follow/Orbit 在最终停车开始时关闭感知门控；RandomRoam 在结束时关闭。没有视差输出订阅者时，上游支持惰性计算的节点可跳过匹配；RViz、rosbag 订阅视差会使空闲计算重新活跃。不能把旧部署“4 Hz、1.4 核、空闲 2%”当作当前 RK3588 的性能保证。

cancel/Service ACK 仅表示受理。成功任务未确认停稳会改报 STOP_UNCONFIRMED；取消/失败停车等待超时时保留原结果。因此 CANCELED 不是物理停稳证明，后续动作需要自行核对停车状态。

## 5. 分阶段验收与收尾

首次保持 `enable_motion=false`，核对接口、输入、门控和诊断：

```bash
ros2 action list -t
ros2 interface show go2_uwb_behavior/action/OrbitUwbOnce
ros2 topic info /cmd_vel --verbose
ros2 topic echo --once --qos-durability transient_local --qos-reliability reliable \
  /go2_uwb_behavior/compute_enable
ros2 topic echo /go2/behavior_diagnostics
ros2 topic echo /stereo/obstacle_diagnostics
ros2 topic echo /go2_uwb_local_follow/planner_diagnostics
```

IDLE 门控为 false；接受任务后为 true。检查三种 Goal 的受理、互斥、取消、STOP 拒绝新任务及 IDLE 解除。禁止运动时环绕/漫游不能实际完成路线，不应把其超时当作规划成功测试。

实机测试另行安排：先低速跟随、取消、输入断流和阻塞停车，再验证单次目标与一周环绕。等待真实终态并观察新鲜 odom/底盘状态，不只检查日志或 ACK。本次文档核对没有执行这些运动测试。

收尾只关闭本次自己启动的 launch/进程，通常在对应终端 Ctrl+C；确认活动任务和底盘状态，再停止外部驱动。不要照搬旧设备的全局 pkill 或未知 cleanup.sh，以免影响其他正在运行的任务。

## 6. 排障

| 现象 | 优先检查 |
| --- | --- |
| NOT_READY | UWB/odom/双目/TF 是否就绪，首帧是否在就绪窗口内 |
| INPUT_TIMEOUT | 对应任务需要的输入是否新鲜，规划器命令是否持续更新 |
| 合法空点云 | 看有效深度、时间戳和诊断；无障碍场景可以为空 |
| 门控或接口不可见 | 各终端 ROS_DOMAIN_ID、ROS_LOCALHOST_ONLY、RMW 与 overlay 是否一致 |
| 输出正常但底盘不走 | 外部桥接、遥控模式、enable_motion 和速度控制权 |
| 停车始终不确认 | 新鲜 odom、twist 偏置、pose 稳定性与安装参数 |
| 两路速度交错 | 是否重复启动跟随/规划器，是否同时执行 Nav2 或其他动作 |
