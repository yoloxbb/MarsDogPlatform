# 核心接口

本文描述 `marsdog_core` 当前可直接调用的主要 Python 接口。下划线开头的方法属于内部实现，不作为稳定接口列出。ROS2 联调优先使用[话题](话题.md)协议。

## MarsdogNeedSystem

构造：

```python
MarsdogNeedSystem(
    configDir=None,
    randomGenerator=None,
    timeProvider=None,
)
```

| 方法 | 返回 | 作用/异常规则 |
|---|---|---|
| `GetDemandValue(demandType)` | int | 读取单需求；未知类型抛 `ValueError` |
| `SetDemandValue(demandType, value)` | bool | 写入并限制 0..100；非法类型返回 false；写 Energy 会清小数耗电余量 |
| `GetAllDemands()` | dict | 返回副本 |
| `IsDemandUrgent(demandType)` | bool | 实际含义是是否越过首次 triggerThreshold |
| `GetMostUrgentDemand()` | string | 已触发需求按原始值选最大；无触发返回空字符串 |
| `GetDemandLevelValue(demandType, value=None)` | dict | 计算 NORMAL/TRIGGERED/URGENT/OVERFLOW 和阈值字段 |
| `GetAllDemandLevels()` | dict | 全部等级明细 |
| `GetDemandLevelEventsValue()` | dict | 各需求当前等级事件名 |
| `GetDemandSignalSnapshotValue()` | dict | 返回内部等级快照结构 |
| `GetDemandSignalEventsValue(timestamp=None)` | list | 消费等级变化/完成后重发，调用本身会刷新快照 |
| `GetAllDemandSignals()` | list | 当前所有已触发需求，不消费边沿 |
| `GetInternalNeedStateValue(timestamp=None)` | dict | 构造不带 `timeContext` 的 V2 状态核心载荷 |
| `IsDemandLocked(currentTime=None)` | bool | 判断 00:00..06:00 并写入运行态锁定标记 |
| `UpdateNaturalDemandsByTime(currentTime=None, energyElapsedSeconds=None)` | dict | 执行一次统一自然需求更新 |
| `ResetDemandsToMorningInitialValues(currentTime=None)` | dict | 随机重置非 Energy 需求并必要时唤醒 |
| `GetMorningResetKey(currentTime=None)` | string | datetime 使用日期；只有小时输入时为 `static-day` |
| `ApplyInterruptedDemandDelta(demandType)` | bool | 直接应用单次中断需求变化 |
| `ExecuteDemandInterrupted(demandType)` | bool | 中断需求并调用行为结果情绪接口；分离系统中情绪调用实际无效 |
| `GetDemandTypeByAction(actionType)` | string/null | 查 `actionDemandMap`，不规范化输入 |
| `OnVisualEvent(metadata=None)` | list | 返回输入 events；只识别主人在场副作用 |
| `OnAudioEvent(metadata=None)` | list | 返回非空事件名；识别主人声纹/叫名副作用 |
| `OnTactileEvent(metadata=None)` | list | 返回非空事件名，不改需求 |
| `OnBehaviorResultEvent(resultData=None)` | bool | 校验、去重并结算需求 |

### 单需求行为接口

| 方法 | 返回 | 实际作用 |
|---|---|---|
| `InitializeMorningHunger()` | int | Hunger 随机 60..70 |
| `UpdateHungerByTime(currentTime=None)` | int | 应用单 Tick 增长 |
| `GetHungerRecoveryValue(foodType, portions, eatEfficiency)` | int | 计算但不写状态；非法枚举抛异常 |
| `ExecuteEat(...)` / `Feed(...)` | bool | 直接结算进食及 Bladder/Cleanliness 联动 |
| `InitializeMorningBladder()` | int | Bladder 随机 20..30 |
| `UpdateBladderByTime(currentTime=None)` | int | 应用单 Tick 增长 |
| `ApplyBladderAfterEat(hungerBeforeEat)` | int | 按进食前 Hunger 增加 Bladder |
| `ApplyBladderEventBonus(eventType)` | bool | 仅接受 `AfterDrink`、`AfterPlay` |
| `ExecuteDefecate()` / `Defecate()` | bool | Bladder 归零 |
| `InitializeMorningSleepiness()` | int | Sleepiness 随机 10..15 |
| `UpdateSleepinessByTime(currentTime=None)` | int | 清醒增长/强制值，或睡眠恢复 |
| `UpdateSleepTriggerState(currentTime=None)` | bool | 刷新 `sleepActionAllowed` |
| `IsSleepActionAllowed(currentTime=None)` | bool | 检查阈值和时段 |
| `SetLightsOffValue(isLightsOff)` | None | 改关灯上下文并刷新允许状态，不立即把 Sleepiness 写成 90 |
| `IsSleeping()` | bool | 当前是否睡眠 |
| `GetSleepDepthValue()` | string | `Shallow` 或 `Deep` |
| `ExecuteSleep()` | bool | 无条件进入 Shallow，不自行检查允许状态 |
| `ApplySleepRecovery(currentTime=None)` | int | 执行一次 Shallow/Deep 恢复 |
| `WakeUp(currentTime=None)` | None | 清睡眠状态并刷新允许状态 |
| `IsForcedSleepTime(currentTime=None)` | bool | 凌晨或关灯 |
| `IsForcedAwakeTime(currentTime=None)` | bool | 06:00..08:00 |
| `IsDaytimeSleepEntryTime(currentTime=None)` | bool | 06:00..00:00 |
| `InitializeMorningCleanliness()` | int | Cleanliness 随机 5..15 |
| `UpdateCleanlinessByTime(currentTime=None)` | int | 应用单 Tick 增长 |
| `ApplyCleanlinessAfterEat()` | int | Cleanliness +20 |
| `ExecuteGroom()` / `Groom()` | bool | Cleanliness -50 |
| `InitializeStartupEnergy()` | int | 按启动电量写 Energy |
| `InitializeMorningEnergy()` | int | 兼容直接调用；会重新初始化满电，统一晨起重置不会调用它 |
| `GetBatteryValue()` | int | 返回 `100-Energy` |
| `SetEnergyBatteryValue(batteryValue)` | bool | 电量限制 0..100 后反向写 Energy |
| `UpdateEnergyByTime(currentTime=None, elapsedSeconds=None)` | int | 按耗电公式更新；非法时长抛异常 |
| `ExecuteRecharge()` / `Recharge()` | bool | 充到配置目标 |
| `InitializeMorningSocial()` | int | 按 `k_social` 随机初始化 |
| `UpdateSocialByTime(currentTime=None)` | int | 应用单 Tick 增长 |
| `OnOwnerPresenceChanged(isPresent)` | None | 真/假转换；离场边沿 Social +30 |
| `GetSocialOutcomeRecoveryValue(outcome)` | int/null | 三种成功 outcome 返回恢复值 |
| `InitializeMorningExploration()` | int | 按 `k_curious` 随机初始化 |
| `UpdateExplorationByTime(currentTime=None)` | int | 按时间和 Energy 条件增长 |
| `ExecuteExploration(resultType=None)` | bool | 忽略 resultType，按 Completed -15 |

`currentTime` 支持 `None`、`datetime`、`time` 或整数小时。整数小时不校验 0..23，调用方应只传合法小时。

## MarsdogEmotionSystem

构造：

```python
MarsdogEmotionSystem(
    configDir=None,
    randomGenerator=None,
    timeProvider=None,
    eventTimeProvider=None,
    eventDeduplicationWindowSeconds=None,
)
```

| 方法 | 返回 | 作用/异常规则 |
|---|---|---|
| `GetEmotionValue(emotionType)` | int | 未知类型抛 `ValueError` |
| `SetEmotionValue(emotionType, value)` | bool | 写入并限制 0..100；非法返回 false |
| `GetAllEmotions()` | dict | 返回副本 |
| `GetDominantEmotion()` | string | 取当前最大值，不检查触发阈值 |
| `ApplyEmotionDelta(emotionType, delta)` | bool | 增量转整数后写入 |
| `ApplyEmotionEvent(eventName, metadata=None)` | bool | 查映射、事件名去重、乘性格/metadata 后应用 |
| `GetEmotionEventMappingValue(eventName)` | dict | 返回映射浅副本；未知事件返回空对象 |
| `GetLastEmotionEventResultValue()` | dict | 返回最近事件结果浅副本 |
| `GetEmotionEventDeduplicationWindowSecondsValue()` | float | 读取当前窗口 |
| `ApplyEmotionDecay(elapsedSeconds=1.0)` | dict | 按真实秒规则衰减；负数按 0 秒 |
| `IsEmotionTriggered(emotionType, value=None)` | bool | 普通情绪按阈值，Calm 按兜底 |
| `IsCalmFallbackActive()` | bool | 其他五类均未触发 |
| `GetEmotionSignalSnapshotValue()` | dict | 六类触发布尔快照 |
| `GetEmotionSignalEventsValue(timestamp=None)` | list | 消费上升沿；Calm 每次调用都可返回 |
| `GetAllEmotionSignals()` | list | 当前触发信号，不消费边沿 |
| `OnEmotionChanged(callback)` | None | 注册 `(emotion, old, new)` 回调，无注销接口 |
| `ApplyActionResultEmotion(resultType)` | bool | 使用内部三类结果名和随机规则 |
| `OnAudioEvent(metadata=None)` | list | 处理单事件 |
| `OnVisualEvent(metadata=None)` | list | 逐项处理 events |
| `OnTactileEvent(metadata=None)` | list | 处理单事件 |
| `OnBehaviorResultEvent(resultData=None)` | bool | 通用校验、独立去重并映射情绪 |
| `GetEmotionStateValue(timestamp=None)` | dict | 构造不带 `timeContext` 的 V2 状态核心载荷 |

`eventDeduplicationWindowSeconds` 必须可转有限非负浮点且不能是布尔值；ROS2 节点未暴露此构造参数。

## MarsdogPersonalitySystem

| 方法 | 返回 | 作用 |
|---|---|---|
| `SetPersonalityProfileValue(profileName)` | bool | 应用预设；Custom 只改名称 |
| `SetPersonalityParamValue(paramName, value)` | bool | 写单项并切 Custom |
| `SetPersonalityParamsValue(params)` | bool | 要求完整 A/O/E/C 并切 Custom |
| `SetPersonalityStateValue(stateData)` | bool | 同步完整 params 和 profile |
| `GetPersonalityProfileValue()` | string | 当前预设名 |
| `GetAllPersonalityParams()` | dict | 返回参数副本 |
| `GetPersonalityStateValue(timestamp=None)` | dict | V1 状态和系数 |
| `GetSocialPersonalityCoefficientValue()` | float | 等于 Joy 系数 |
| `GetEmotionPersonalityCoefficientValue(emotionType)` | float | 计算单情绪系数 |

需求和情绪系统也混入这些方法，但推荐让 `personality_node` 成为权威来源，再通过 `/personality/state` 同步。

## MarsdogTimeController

| 方法 | 返回 | 作用 |
|---|---|---|
| `GetTimeScaleValue()` | int | 当前倍率 |
| `GetTimeRevisionValue()` | int | 倍率修订号 |
| `GetVirtualStartDateTimeValue()` | datetime | 带时区起点 |
| `GetVirtualDateTimeValue()` | datetime | 当前虚拟时间 |
| `GetVirtualTimestampValue()` | float | 虚拟 Unix 秒 |
| `GetRealIntervalValue(virtualSeconds)` | float | 虚拟间隔除以倍率，非正值抛异常 |
| `SetTimeScaleValue(timeScale)` | bool | 连续切换倍率 |
| `SetVirtualDateTimeValue(virtualDateTime)` | bool | 重建当前锚点，不改 revision |
| `SetTimeContextValue(timeContext)` | bool | 同步远端权威上下文 |
| `GetTimeContextValue(virtualDateTime=None, wallTimestamp=None)` | dict | 构造时间上下文 |

## 调度器

| 类 | 关键方法 | 语义 |
|---|---|---|
| `VirtualTickScheduler` | `GetDueTickDateTimesValue(currentDateTime)` | 返回并消费所有到期 datetime，不合并 |
| `VirtualTickScheduler` | `AlignToDateTimeValue(currentDateTime, includeCurrent=False)` | 快速对齐，避免回放完整历史 |
| `RealTimeTickScheduler` | `GetDueTickCountValue(currentSeconds)` | 返回并消费到期的真实 Tick 数 |

两个调度器的间隔都必须为有限正数；虚拟调度器要求正数，但没有显式有限数检查。

## 状态重置

`MarsdogState.ResetToDefault()` 会恢复需求、情绪、性格、睡眠、主人、锁定、耗电余量和去重记录。它不会重新加载配置，也不会重建系统保存的需求/情绪信号快照；若测试在重置后立即读取边沿事件，应注意快照仍属于重置前系统对象。
