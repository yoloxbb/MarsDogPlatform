# 联调指南

## 1. 环境与构建

要求 Python 3.10+ 和可用的 ROS2 Python 环境。先加载目标 ROS2 环境，再在仓库根目录构建：

```bash
cd /home/bird/Marsdog
colcon build --packages-select marsdog_need_emotion --symlink-install
source install/setup.bash
```

如果仓库被放在更大的 colcon 工作区中，应在该工作区根目录执行同样命令，并加载该工作区的 `install/setup.bash`。

## 2. 启动核心节点

标准 1 倍：

```bash
ros2 launch marsdog_need_emotion internal_need_emotion.launch.py
```

24 倍、固定随机种子、从虚拟 06:00 开始：

```bash
ros2 launch marsdog_need_emotion internal_need_emotion.launch.py \
  time_scale:=24 \
  virtual_start_time:=06:00 \
  random_seed:=12345
```

启用生产凌晨加速，把每个虚拟 00:00..06:00 压缩到 30 个真实秒：

```bash
ros2 launch marsdog_need_emotion internal_need_emotion.launch.py \
  time_scale:=24 \
  virtual_start_time:=00:00 \
  random_seed:=12345 \
  midnight_acceleration_enabled:=true \
  midnight_duration_seconds:=30.0
```

## 3. 先检查拓扑和 QoS

```bash
ros2 node list
ros2 topic list
ros2 topic info --verbose /simulation/time_state
ros2 topic info --verbose /behavior/result_event
ros2 topic info --verbose /internal_need/signal_event
ros2 topic info --verbose /emotion/signal_event
```

核心节点应包含：`/time_controller_node`、`/personality_node`、`/internal_need_node`、`/emotion_engine_node`。

## 4. 观察输出

分别在终端运行：

```bash
ros2 topic echo /simulation/time_state std_msgs/msg/String
ros2 topic echo /personality/state std_msgs/msg/String
ros2 topic echo /internal_need/state std_msgs/msg/String
ros2 topic echo /internal_need/signal_event std_msgs/msg/String
ros2 topic echo /emotion/state std_msgs/msg/String
ros2 topic echo /emotion/signal_event std_msgs/msg/String
```

`String.data` 是转义后的 JSON 字符串，可用 `jq` 辅助查看：

```bash
ros2 topic echo --field data /internal_need/state | jq -R 'fromjson?'
```

## 5. 注入感知事件

表扬：

```bash
ros2 topic pub --once /perception/audio_event std_msgs/msg/String \
  "{data: '{\"schema_version\":\"1.0\",\"timestamp\":1789460001.0,\"event_type\":\"EVT_VOICE_PRAISE\",\"masterId\":\"owner-1\"}'}"
```

看到主人和玩具：

```bash
ros2 topic pub --once /perception/visual_event std_msgs/msg/String \
  "{data: '{\"schema_version\":\"1.0\",\"timestamp\":1789460002.0,\"events\":[\"EVT_VISION_MASTER\",\"EVT_VISION_TOY\"]}'}"
```

摸头：

```bash
ros2 topic pub --once /perception/tactile_event std_msgs/msg/String \
  "{data: '{\"schema_version\":\"1.0\",\"timestamp\":1789460003.0,\"event_type\":\"EVT_TACTILE_HEAD_PET\",\"source\":\"manual\"}'}"
```

注意同名情绪事件 10 秒内只生效一次。若要连续验证，换事件名或等待满 10 个真实秒。

## 6. 注入行为结果

先等待或通过测试 API 让 Hunger 达到触发值，然后发送完成进食：

```bash
ros2 topic pub --once /behavior/result_event std_msgs/msg/String \
  "{data: '{\"schema_version\":\"1.0\",\"timestamp\":1789460010.0,\"event_id\":\"eat-completed-001\",\"action_type\":\"ACTION_EAT\",\"demand_type\":\"Hunger\",\"result_type\":\"COMPLETED\",\"metadata\":{\"foodType\":\"NormalFood\",\"portions\":1,\"eatEfficiency\":\"Full\"}}'}"
```

预期需求变化：Hunger -20；Bladder 按进食前 Hunger +0/+20/+25；Cleanliness +20。情绪同时按完成结果随机变化。

发送探索中断：

```bash
ros2 topic pub --once /behavior/result_event std_msgs/msg/String \
  "{data: '{\"schema_version\":\"1.0\",\"timestamp\":1789460011.0,\"event_id\":\"explore-interrupted-001\",\"action_type\":\"ACTION_EXPLORE\",\"demand_type\":\"Exploration\",\"result_type\":\"INTERRUPTED\",\"metadata\":{}}'}"
```

预期：Exploration -20，Anxiety 随机 +3..5。每次测试必须换新的 `event_id`。

## 7. 修改性格和时间倍率

应用预设：

```bash
ros2 param set /personality_node profile SunnyExplorer
```

设置自定义参数：

```bash
ros2 param set /personality_node A 65
ros2 param set /personality_node O 70
ros2 param set /personality_node E 80
ros2 param set /personality_node C 55
```

第一条自定义参数写入就会把 profile 切换为 Custom。运行时改时间倍率只改权威时间节点：

```bash
ros2 param set /time_controller_node time_scale 12
```

需求和情绪节点通过 `/simulation/time_state` 自动同步，不需要分别设置。

## 8. ONE1000 联调

随核心节点启动：

```bash
ros2 launch marsdog_need_emotion internal_need_emotion.launch.py \
  one1000_tactile_enabled:=true \
  one1000_serial_port:=/dev/ttyUSB1 \
  one1000_detection_mode:=distance \
  one1000_distance_threshold_cm:=10.0 \
  one1000_touch_cooldown_seconds:=2.0
```

单独启动硬件适配：

```bash
ros2 launch marsdog_need_emotion one1000_tactile.launch.py \
  serial_port:=/dev/ttyUSB1 \
  detection_mode:=distance
```

观察：

```bash
ros2 topic echo /one1000/status std_msgs/msg/String
ros2 topic echo /perception/tactile_event std_msgs/msg/String
```

详细串口和判定规则见[触觉硬件](触觉硬件.md)。

## 联调验收清单

- 所有消息都是 `std_msgs/msg/String`，且 `data` 是 JSON 对象文本。
- `/simulation/time_state` 只有一个权威发布方。
- 性格和时间话题能以 Transient Local 到达晚启动节点。
- 输入动作属于 13 个可结算动作，`demand_type` 与动作一致。
- 每条行为结果使用唯一、非空 `event_id`。
- 感知事件名在 50 个情绪映射内，视觉用 `events`，声音/触觉用 `event_type`。
- 业务同时读取墙上 `timestamp` 与虚拟 `timeContext.virtualDateTime`，不混用。
- 需求按严格大于阈值触发，情绪按大于等于阈值触发。
- 对 Social 拒绝/超时、睡眠完成、TIMEOUT 的需求/情绪差异已有明确处理预期。
