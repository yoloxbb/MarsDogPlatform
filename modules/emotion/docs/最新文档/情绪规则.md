# 情绪规则

## 计算模型

六个情绪都是独立整数 0..100，不要求总和为 100。感知事件的单个情绪增量按下式计算：

```text
实际增量 = round(基础增量 × 对应情绪的性格系数 × metadata 倍率)
新值 = clamp(旧值 + 实际增量, 0, 100)
```

使用 Python 的 `round` 后再转整数。行为结果产生的随机情绪变化不乘性格系数。

## 初始值和触发阈值

| 情绪 | 初始值 | 触发规则 | 自然衰减/真实秒 |
|---|---:|---|---:|
| Joy | 0 | `>= 30` | -2 |
| Excite | 0 | `>= 40` | -3 |
| Anxiety | 0 | `>= 25` | 0 |
| Fear | 0 | `>= 30` | -4 |
| Curious | 0 | `>= 20` | -2 |
| Calm | 30 | 无其他情绪触发时兜底 | 0 |

配置里 Calm 写有 `>=0`，但实际代码不用 Calm 自身数值判断，而是检查其他五类情绪均未触发。配置里的 Fear `freezeThreshold=60` 当前也没有执行入口。

## 输入去重

- 同一个 `event_type` 在真实单调时钟 10 秒内只接受第一次；恰好满 10 秒可再次接受。
- 不同事件名独立计时，声音、视觉、触觉入口共用同一情绪系统的去重表。
- 窗口可在创建核心系统时配置为非负数，ROS2 节点当前没有暴露对应参数。
- 窗口为 0 时关闭去重。
- 单调时钟回退时，将当前事件视作新的时间基准并接受。
- 输入没有使用 `event_id` 去重，只有事件名和本节点接收时间参与判断。

## metadata 倍率

只有两个事件配置倍率：

| 事件 | 条件 | 倍率 |
|---|---|---:|
| `EVT_AUDIO_LOUD` | `loudnessDb > 80` | ×1.5 |
| `EVT_AUDIO_LOUD` | `loudness_db > 80` | ×1.5 |
| `EVT_VOICE_PRAISE` | `masterId` 为真 | ×1.2 |
| `EVT_VOICE_PRAISE` | `master_id` 为真 | ×1.2 |
| `EVT_VOICE_PRAISE` | `speakerIsMaster` 为真 | ×1.2 |

每条命中规则都会相乘，并不是别名“任选一个”。如果同一大声事件同时带两个大于 80 的响度字段，最终倍率为 2.25；表扬事件三个主人字段都为真时，倍率为 1.728。这是当前源码的精确行为。

## 性格影响

每个基础增量分别乘该情绪的性格系数。默认 A/O/E/C 都为 50 时，大部分系数为 1.0，但 Curious 为 1.15；因此 `EVT_VISION_TOY` 的 Curious 基础 +20 实际为 +23。

性格只影响事件发生后的增量，不追溯重算已有情绪值。公式和预设系数见[性格规则](性格规则.md)。

## 行为结果影响

行为结果不走上面的 50 个事件表，不乘性格系数，而是使用闭区间随机值：

- 完成：Joy +10..20、Calm +5..10、Anxiety -15..-5。
- 失败或超时：Anxiety +5..15。
- 中断或取消：Anxiety +3..5。
- 开始：无变化。

详见[衰减规则](衰减规则.md)。

## 信号规则

- 五个普通情绪达到阈值时发布一次上升沿；阈值内继续上升不重复发布。
- 普通情绪跌破阈值时只更新内部快照，不发布恢复事件。
- 跌破后再次达到阈值，重新发布上升沿。
- 任意普通情绪触发时 Calm 立即不再作为兜底。
- 没有普通情绪触发时，Calm 每次检查都发布；ROS2 节点以真实 1 Hz 驱动该检查。
- 多个普通情绪同一次检查进入阈值时，会分别发布多条事件。

## 最近事件结果

每次成功应用感知事件后，`/emotion/state.lastEmotionEventResult` 更新为：

```json
{
  "eventName": "EVT_VOICE_PRAISE",
  "appliedDeltas": {"Joy": 36, "Excite": 24, "Calm": 6},
  "metadataMultiplier": 1.2,
  "metadata": {"event_type": "EVT_VOICE_PRAISE", "masterId": true}
}
```

行为结果和自然衰减不会覆盖这一对象。
