# 输入

## 通用要求

发布到本模块的消息类型必须是 `std_msgs/msg/String`，`data` 必须是 JSON 对象。除各节列出的字段外，额外字段通常会保留在事件元数据中或被忽略。

## 视觉事件

话题：`/perception/visual_event`

最小格式：

```json
{
  "schema_version": "1.0",
  "timestamp": 1789460000.125,
  "events": ["EVT_VISION_MASTER", "EVT_VISION_ANIMAL_GREET"]
}
```

| 字段 | 类型 | 必需 | 实际规则 |
|---|---|---|---|
| `events` | `string[]` 或 `string` | 是 | 列表逐项转字符串；单字符串转成单元素列表；空值不处理 |
| 其他字段 | 任意 | 否 | 整个对象会作为每个情绪事件的 metadata；当前视觉规则没有元数据倍率 |

需求系统只对 `EVT_VISION_MASTER` 有副作用：把 `ownerPresent` 设为 `true`。情绪系统只处理[情绪规则](情绪规则.md)中存在的视觉事件；未知事件忽略。

## 声音事件

话题：`/perception/audio_event`

```json
{
  "schema_version": "1.0",
  "timestamp": 1789460001.25,
  "event_type": "EVT_VOICE_PRAISE",
  "masterId": "owner-1"
}
```

| 字段 | 类型 | 必需 | 实际规则 |
|---|---|---|---|
| `event_type` | 任意可转字符串值 | 是 | 转字符串后不能为空；未知事件对情绪无效 |
| `loudnessDb` / `loudness_db` | 数值 | 特定事件可选 | `EVT_AUDIO_LOUD` 且值 `> 80` 时，每个命中字段各乘 1.5 |
| `masterId` / `master_id` / `speakerIsMaster` | 任意真值 | 特定事件可选 | `EVT_VOICE_PRAISE` 时，每个真值字段各乘 1.2 |

`EVT_VOICE_MASTER_ID` 或 `EVT_VOICE_CALL_NAME` 会把需求系统的主人状态设为在场。代码没有通过此话题处理主人离场。

## 触觉事件

话题：`/perception/tactile_event`

```json
{
  "schema_version": "1.0",
  "timestamp": 1789460002.5,
  "event_type": "EVT_TACTILE_HEAD_PET",
  "source": "ONE1000",
  "sensorType": "UWB_DISTANCE",
  "touchState": "STARTED"
}
```

仅 `event_type` 参与核心计算。需求系统不改变任何需求；情绪系统按事件映射处理。ONE1000 会补充距离或雷达诊断字段，详见[触觉硬件](触觉硬件.md)。

## 行为结果

话题：`/behavior/result_event`

推荐格式：

```json
{
  "schema_version": "1.0",
  "timestamp": 1789460003.75,
  "event_id": "behavior-result-0001",
  "action_type": "ACTION_EAT",
  "demand_type": "Hunger",
  "result_type": "COMPLETED",
  "metadata": {
    "foodType": "NormalFood",
    "portions": 1,
    "eatEfficiency": "Full"
  }
}
```

### 字段校验

| 标准字段 | 兼容别名 | 类型 | 必需 | 实际规则 |
|---|---|---|---|---|
| `event_id` | `eventId` | 任意可转字符串 | 建议必填 | trim 后为空视为缺失；用于最近 256 个 ID 去重 |
| `timestamp` | 无 | 任意 | 否 | 原样保留，但当前需求/情绪结算不读取、不校验 |
| `action_type` | `actionType` | 字符串 | 是 | 必须是 13 个可结算动作之一 |
| `demand_type` | `demandType` | 字符串 | 否 | 缺失时由动作补全；显式填写必须合法且与动作映射一致 |
| `result_type` | `resultType` | 值可转字符串 | 是 | 转大写后必须是六个外部结果之一 |
| `metadata` | 无 | 对象或 `null` | 否 | 缺失或 `null` 变成 `{}`；其他类型拒绝整条消息 |

同一个 `event_id` 在需求系统和情绪系统内分别去重；两者不是共享存储。未填写 `event_id` 时不去重。

### 动作 metadata

| 动作 | 字段 | 可用值/规则 | 缺省 |
|---|---|---|---|
| `ACTION_EAT` | `foodType` / `food_type` | `PremiumFood`、`NormalFood`、`Snack` 及中文别名 | `NormalFood` |
| `ACTION_EAT` | `portions` | 可转浮点；负数按 0 份处理 | `1` |
| `ACTION_EAT` | `eatEfficiency` / `eat_efficiency` | `Full`、`HalfInterrupted` 及中文别名 | `Full` |
| `ACTION_RECHARGE` | `energyValue` / `energy_value` / `batteryValue` | 可转整数的硬件电量百分比，随后限制到 0..100 | 配置目标 100 |
| 五类 Social 动作 | `socialOutcome` / `social_outcome` | `OwnerInteraction`、`DogHumanResponded`、`DogAnimalResponded`、`Rejected`、`TimedOut` 或空 | 空 |
| 三类 Exploration 动作 | 任意 | 当前全部忽略，统一按 Completed 恢复 | 无 |

完整的结果差异和数值变化见[衰减规则](衰减规则.md)。

## 性格状态

话题：`/personality/state`

```json
{
  "schema_version": "1.0",
  "timestamp": 1789460004.0,
  "profile": "SunnyExplorer",
  "params": {"A": 90, "O": 80, "E": 95, "C": 70},
  "coefficients": {"Joy": 1.82, "Social": 1.82}
}
```

计算节点的实际校验规则：

- `params` 必须是对象，并完整包含 `A`、`O`、`E`、`C`；值须可转整数、非布尔且在 0..100。
- `profile` 缺省为 `Custom`；非 Custom 值必须是已配置预设。
- `coefficients`、`schema_version`、`timestamp` 均不参与同步，系数由接收端重新计算。

## 权威时间状态

话题：`/simulation/time_state`

```json
{
  "schema_version": "1.0",
  "timestamp": 1789460005.0,
  "event_type": "TIME_TICK",
  "tickSequence": 125,
  "timeContext": {
    "mode": "custom",
    "scale": 24,
    "revision": 0,
    "virtualStartDateTime": "2026-09-15T06:00:00+08:00",
    "virtualDateTime": "2026-09-15T06:02:05+08:00",
    "virtualTimestamp": 1789423325.0,
    "virtualElapsedSeconds": 125.0,
    "wallTimestamp": 1789460005.0
  }
}
```

允许的 `event_type`：`TIME_INITIALIZED`、`TIME_TICK`、`TIME_MODE_CHANGED`、`TIME_TEST_STEP`、`TIME_ACCELERATION_CHANGED`、`TIME_ACCELERATED_STEP`。

接收端要求：

- `timeContext` 必须是对象。
- `scale` 必须是整数 1..100，布尔值、字符串和浮点数均拒绝。
- `virtualStartDateTime` 与 `virtualDateTime` 必须是带时区的 ISO 8601 时间，且当前时间不能早于起点。
- `revision` 转整数后必须不小于 0。
- 可选 `effectiveScale` 必须是 int/float 且非布尔，代码用 `<=0` 拒绝非正数；当前没有显式有限数检查，因此 Python JSON 解析器接受的 NaN/Infinity 也可能通过，这是实现缺口，不应由调用方发送。
- 可选 `midnightAcceleration` 必须是对象。

计算节点不核对 `mode`、`virtualTimestamp`、`virtualElapsedSeconds`、`wallTimestamp` 与 ISO 时间是否互相一致，而是以两个 ISO 时间、`scale` 和 `revision` 为主要同步值。
