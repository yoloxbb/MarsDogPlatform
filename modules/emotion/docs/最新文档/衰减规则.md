# 衰减规则

本文把“数值随时间降低”和“动作结算导致需求降低”统一列出。需求数值越低通常代表被满足；情绪降低代表该情绪平复。

## 情绪自然衰减

情绪衰减使用真实时间，不随虚拟时间倍率加速。节点以真实 1 Hz 调度，延迟时逐秒补算。

| 情绪 | 每真实秒变化 | 是否自然衰减 |
|---|---:|---|
| Joy | -2 | 是 |
| Excite | -3 | 是 |
| Anxiety | 0 | 否 |
| Fear | -4 | 是 |
| Curious | -2 | 是 |
| Calm | 0 | 否 |

单次 API 公式：

```text
newValue = round(max(0, oldValue - rate × max(0, elapsedSeconds)))
```

最终仍限制在 0..100。Anxiety 和 Calm 只能被外部事件、行为结果或直接 API 写入改变。

## 动作完成对需求的影响

| 动作 | 结果 | 主需求变化 | 联动变化 | 必需/关键 metadata |
|---|---|---|---|---|
| `ACTION_EAT` | `COMPLETED` | Hunger 减少食物恢复值 | Bladder +0/+20/+25；Cleanliness +20 | `foodType`、`portions`、`eatEfficiency` 均可缺省 |
| `ACTION_DEFECATE` | `COMPLETED` | Bladder 设为 0 | 无 | 无 |
| `ACTION_SLEEP` | `STARTED` | 不立即降低 | 进入 14 Tick 浅睡，随后按状态机恢复 | 无 |
| `ACTION_SLEEP` | `COMPLETED` | 需求系统不处理 | 情绪系统仍会按满足结算 | 无 |
| `ACTION_GROOM` | `COMPLETED` | Cleanliness -50 | 无 | 无 |
| `ACTION_RECHARGE` | `COMPLETED` | `Energy = 100 - batteryValue` | 清空耗电小数余量 | 电量字段可缺省，缺省按 100% |
| 五类 Social 动作 | `COMPLETED` | 按 `socialOutcome` 为 0/-15/-20/-25 | 无 | 见[需求规则](需求规则.md) |
| 三类 Exploration 动作 | `COMPLETED` | Exploration -15 | 无 | metadata 被忽略 |

所有变化都截断到 0..100。

## 中断、取消和超时对需求的影响

需求系统把 `INTERRUPTED`、`CANCELLED`、`TIMEOUT` 统一视为中断结算：

| 映射需求 | 单次变化 |
|---|---:|
| Bladder | -40 |
| Hunger | -20 |
| Sleepiness | -20，并在睡眠时先唤醒 |
| Cleanliness | -20 |
| Energy | -20 |
| Social | -20 |
| Exploration | -20 |

这里的“中断导致需求降低”是源码当前规则。`FAILED` 不改变任何需求，`STARTED` 除睡眠外不改变需求。

## 行为结果对情绪的影响

情绪系统只要动作属于 13 个 `actionDemandMap` 动作，就按结果类型映射。此处不乘性格系数：

| 外部 `result_type` | 内部规则 | 情绪变化，闭区间随机 |
|---|---|---|
| `COMPLETED` | `DemandSatisfied` | Joy +10..+20；Calm +5..+10；Anxiety -15..-5 |
| `FAILED` | `DemandUnsatisfied` | Anxiety +5..+15 |
| `TIMEOUT` | `DemandUnsatisfied` | Anxiety +5..+15 |
| `INTERRUPTED` | `ActionInterrupted` | Anxiety +3..+5 |
| `CANCELLED` | `ActionInterrupted` | Anxiety +3..+5 |
| `STARTED` | 无 | 不改变情绪 |

重要差异：需求系统把 `TIMEOUT` 当中断并降低需求，情绪系统把它当未满足；Social 的 `Rejected`、`TimedOut` 或空结果如果装在 `COMPLETED` 中，需求不降低，但情绪仍按“满足”增加 Joy/Calm；`ACTION_SLEEP + COMPLETED` 也存在同样的情绪结算差异。

两个系统独立处理同一消息。只要通用结构校验通过，情绪系统不会检查动作专属 metadata；例如非法 `energyValue` 或未知 `socialOutcome` 可导致需求结算失败，但情绪系统仍按 `COMPLETED` 结算“满足”。

## 感知事件对情绪的负向变化

感知事件不是自然衰减，但以下事件包含负增量：

| 事件 | 负向变化 |
|---|---|
| `EVT_AUDIO_LOUD` | Excite -10，之后仍乘性格和 metadata 倍率 |
| `EVT_VOICE_SCOLD` | Joy -10 |
| `EVT_VOICE_COMFORT` | Anxiety -25、Fear -15 |
| `EVT_VOICE_SAD` | Calm -5 |
| `EVT_VOICE_NEGATIVE_EMOTION` | Excite -15、Joy -5 |
| `EVT_VISION_MASTER_SAD` | Calm -5 |

所有事件的完整正负增量见[情绪规则](情绪规则.md)。

## 睡眠恢复

睡眠恢复随虚拟 10 分钟需求 Tick 结算：

| 深度 | 每 Tick Sleepiness 变化 | 每 Tick 记录睡眠时长 |
|---|---:|---:|
| Shallow | -2 | +10 分钟 |
| Deep | -15 | +10 分钟 |

普通模式下虚拟时间倍率会改变这些 Tick 到达的真实频率；凌晨离散加速时仍有 36 个虚拟 10 分钟步骤。

## 信号重发与衰减的关系

- 需求变化跨等级：发布新等级事件，包括恢复到 NORMAL 的 `*_RECOVERED`。
- 动作 `COMPLETED` 已结算，但主需求仍停在相同激活等级：重发当前需求事件，`trigger=ACTION_RESULT_STILL_ACTIVE`。
- 中断、取消、超时不会登记这种“动作完成后仍激活”重发；只有实际跨级才发布。
- 普通情绪自然衰减离开阈值时不发布恢复事件；以后再次达到阈值才重新发上升沿。
