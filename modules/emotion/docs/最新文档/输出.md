# 输出

## 通用时间上下文

需求状态、需求信号、情绪状态和情绪信号都会在核心载荷外追加 `timeContext`：

```json
{
  "mode": "custom",
  "scale": 24,
  "revision": 0,
  "virtualStartDateTime": "2026-09-15T06:00:00+08:00",
  "virtualDateTime": "2026-09-15T12:30:00+08:00",
  "virtualTimestamp": 1789446600.0,
  "virtualElapsedSeconds": 23400.0,
  "wallTimestamp": 1789460000.125
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `mode` | string | 1 倍为 `standard_24h`，2 倍为 `demo_12h`，12 倍为 `demo_2h`，其余为 `custom` |
| `scale` | integer | 基础虚拟时间倍率 1..100 |
| `revision` | integer | 每次真正改变倍率加 1 |
| `virtualStartDateTime` | string | 带时区 ISO 8601 起点 |
| `virtualDateTime` | string | 当前消息对应的带时区虚拟时间 |
| `virtualTimestamp` | number | 虚拟 Unix 秒 |
| `virtualElapsedSeconds` | number | 从虚拟起点累计的虚拟秒，最小为 0 |
| `wallTimestamp` | number | 与顶层 `timestamp` 相同的墙上 Unix 秒 |
| `effectiveScale` | number，可选 | 启用凌晨加速时出现；活动期为 `21600 / durationSeconds` |
| `midnightAcceleration` | object，可选 | 启用凌晨加速时出现，字段见[时间规则](时间规则.md) |

## 内部需求状态

话题：`/internal_need/state`，真实时间 1 Hz，V2。

顶层结构：

```json
{
  "schema_version": "2.0",
  "timestamp": 1789460000.125,
  "demands": {
    "Hunger": {
      "value": 71,
      "triggerThreshold": 70,
      "triggerOperator": "gt",
      "urgentThreshold": null,
      "urgentOperator": null,
      "overflowThreshold": 90,
      "triggered": true,
      "urgent": false,
      "overflow": false,
      "level": "TRIGGERED",
      "levelEvent": "NEED_HUNGER_TRIGGERED",
      "levelActive": true
    }
  },
  "levelEvents": {
    "Hunger": "NEED_HUNGER_TRIGGERED"
  },
  "triggered": [
    {
      "type": "Hunger",
      "value": 71,
      "triggerThreshold": 70,
      "triggerOperator": "gt",
      "urgentThreshold": null,
      "urgentOperator": null,
      "urgent": false,
      "overflow": false
    }
  ],
  "sleep": {
    "isSleeping": false,
    "sleepDepth": "Shallow",
    "sleepDurationMinutes": 0,
    "shallowSleepTicksRemaining": 0
  },
  "timeContext": {
    "mode": "custom",
    "scale": 24,
    "revision": 0,
    "virtualStartDateTime": "2026-09-15T06:00:00+08:00",
    "virtualDateTime": "2026-09-15T12:30:00+08:00",
    "virtualTimestamp": 1789446600.0,
    "virtualElapsedSeconds": 23400.0,
    "wallTimestamp": 1789460000.125
  }
}
```

实际 `demands` 和 `levelEvents` 始终包含七类需求；示例为节省篇幅只展示 `Hunger`。`triggered` 只包含越过首次触发线的需求。

单需求字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `value` | integer | 0..100 |
| `triggerThreshold` | integer | 首次触发线 |
| `triggerOperator` | string | 当前均为 `gt` |
| `urgentThreshold` | integer/null | 只有 Social 为 70 |
| `urgentOperator` | string/null | 只有 Social 为 `gt` |
| `overflowThreshold` | integer/null | Hunger、Sleepiness、Energy、Social 配置了满溢线 |
| `triggered` | boolean | 是否越过首次触发线 |
| `urgent` | boolean | 是否越过可选紧急线 |
| `overflow` | boolean | 是否越过可选满溢线 |
| `level` | string | `NORMAL`、`TRIGGERED`、`URGENT`、`OVERFLOW` |
| `levelEvent` | string | 当前等级对应的 `NEED_*` 事件名；正常时为 `*_RECOVERED` |
| `levelActive` | boolean | `level != NORMAL` |

## 内部需求信号

话题：`/internal_need/signal_event`，V2。

```json
{
  "schema_version": "2.0",
  "timestamp": 1789460000.25,
  "event_type": "NEED_SOCIAL_URGENT",
  "demand": "Social",
  "value": 71,
  "level": "URGENT",
  "previousLevel": "TRIGGERED",
  "triggerThreshold": 60,
  "triggerOperator": "gt",
  "urgentThreshold": 70,
  "urgentOperator": "gt",
  "overflowThreshold": 85,
  "overflowOperator": "gt",
  "trigger": "LEVEL_CHANGED",
  "timeContext": {
    "mode": "custom",
    "scale": 24,
    "revision": 0,
    "virtualStartDateTime": "2026-09-15T06:00:00+08:00",
    "virtualDateTime": "2026-09-15T12:30:00+08:00",
    "virtualTimestamp": 1789446600.0,
    "virtualElapsedSeconds": 23400.0,
    "wallTimestamp": 1789460000.25
  }
}
```

`event_type` 规则为：

- `NEED_<大写需求名>_TRIGGERED`
- `NEED_<大写需求名>_URGENT`
- `NEED_<大写需求名>_OVERFLOW`
- `NEED_<大写需求名>_RECOVERED`

`trigger` 为 `LEVEL_CHANGED`，或者在动作完成后需求仍停留在同一激活等级时为 `ACTION_RESULT_STILL_ACTIVE`。后者复用当前 `event_type`，`previousLevel` 与 `level` 相同。

## 情绪状态

话题：`/emotion/state`，V2。

```json
{
  "schema_version": "2.0",
  "timestamp": 1789460001.0,
  "emotions": {
    "Joy": {
      "value": 35,
      "triggerThreshold": 30,
      "triggerOperator": "gte",
      "triggered": true
    },
    "Excite": {
      "value": 0,
      "triggerThreshold": 40,
      "triggerOperator": "gte",
      "triggered": false
    }
  },
  "triggered": [
    {
      "emotion": "Joy",
      "value": 35,
      "eventType": "EMO_JOY_TRIGGERED",
      "triggerThreshold": 30,
      "triggerOperator": "gte"
    }
  ],
  "dominantEmotion": "Joy",
  "personality": {"A": 50, "O": 50, "E": 50, "C": 50},
  "lastEmotionEventResult": {
    "eventName": "EVT_TACTILE_HEAD_PET",
    "appliedDeltas": {"Joy": 25, "Calm": 15, "Excite": 5},
    "metadataMultiplier": 1.0,
    "metadata": {"event_type": "EVT_TACTILE_HEAD_PET"}
  },
  "timeContext": {
    "mode": "custom",
    "scale": 24,
    "revision": 0,
    "virtualStartDateTime": "2026-09-15T06:00:00+08:00",
    "virtualDateTime": "2026-09-15T12:30:01+08:00",
    "virtualTimestamp": 1789446601.0,
    "virtualElapsedSeconds": 23401.0,
    "wallTimestamp": 1789460001.0
  }
}
```

实际 `emotions` 始终包含六类情绪。`lastEmotionEventResult` 在还没有成功处理事件时为 `{}`；之后会原样带回最近输入事件的 metadata。

`dominantEmotion` 只按当前最大数值选择，不要求该情绪已触发。并列最大值由内部字典顺序决定：Joy、Excite、Anxiety、Fear、Curious、Calm 中较靠前者优先。

## 情绪信号

话题：`/emotion/signal_event`，V2。

```json
{
  "schema_version": "2.0",
  "timestamp": 1789460001.25,
  "event_type": "EMO_JOY_TRIGGERED",
  "emotion": "Joy",
  "value": 35,
  "triggerThreshold": 30,
  "triggerOperator": "gte",
  "timeContext": {
    "mode": "custom",
    "scale": 24,
    "revision": 0,
    "virtualStartDateTime": "2026-09-15T06:00:00+08:00",
    "virtualDateTime": "2026-09-15T12:30:01+08:00",
    "virtualTimestamp": 1789446601.0,
    "virtualElapsedSeconds": 23401.0,
    "wallTimestamp": 1789460001.25
  }
}
```

事件名统一为 `EMO_<大写情绪名>_TRIGGERED`。Joy、Excite、Anxiety、Fear、Curious 只在 `false → true` 上升沿发布；回落不发布恢复事件。Calm 是兜底事件，没有其他情绪触发时，每次真实 1 Hz 检查都会发布 `EMO_CALM_TRIGGERED`。

## 权威时间状态

话题：`/simulation/time_state`，V1。

```json
{
  "schema_version": "1.0",
  "timestamp": 1789460003.0,
  "event_type": "TIME_TICK",
  "tickSequence": 10,
  "timeContext": {
    "mode": "custom",
    "scale": 24,
    "revision": 0,
    "virtualStartDateTime": "2026-09-15T06:00:00+08:00",
    "virtualDateTime": "2026-09-15T12:30:03+08:00",
    "virtualTimestamp": 1789446603.0,
    "virtualElapsedSeconds": 23403.0,
    "wallTimestamp": 1789460003.0
  }
}
```

`timeContext` 使用本文第一节的完整结构。正式时间节点的 `tickSequence` 在普通 Tick 每次加 1；凌晨每个 10 分钟加速步骤加 600，所以仍代表累计虚拟秒序号。独立 `midnight_test_node` 是例外，其 `tickSequence` 直接使用步骤号 0..36。

启用凌晨加速后，时间上下文增加：

```json
{
  "effectiveScale": 720.0,
  "midnightAcceleration": {
    "enabled": true,
    "active": true,
    "durationSeconds": 30.0,
    "virtualStepSeconds": 600,
    "stepSequence": 1,
    "stepCount": 36
  }
}
```

  "event_type": "EVT_TACTILE_HEAD_PET",
  "source": "ONE1000",

## ONE1000 状态

话题：`/one1000/status`，真实时间 1 Hz，V1。

| 顶层字段 | 类型 | 说明 |
|---|---|---|
| `schema_version` | string | 固定 `1.0` |
| `timestamp` | number | 墙上 Unix 秒 |
| `source` | string | 固定 `ONE1000` |
| `serialPort` | string | 串口路径 |
| `serialOpen` | boolean | 节点认为串口是否打开 |
| `connected` | boolean | 最近 2.5 秒内有心跳、有效协议包或任意 UART 字节之一 |
| `detection` | object | 模式、距离阈值、当前是否处于距离触发区 |
| `protocol` | object | 协议/UART 活跃状态及字节、包计数和年龄 |
| `commands` | object | 启动命令是否排队、发送/响应计数、最近响应 |
| `heartbeat` | object/null | 最近 0x59 心跳及年龄 |
| `sentryStatus` | object/null | 最近 0x54 雷达检测及年龄 |
| `position` | object/null | 最近 0xC5 定位、RSSI、质量及阈值判断 |

完整嵌套字段见[触觉硬件](触觉硬件.md)。

## 凌晨测试结果

话题：`/simulation/midnight_test_result`，结束时发布一次，V1。

```json
{
  "schema_version": "1.0",
  "timestamp": 1789460035.0,
  "event_type": "MIDNIGHT_TEST_COMPLETED",
  "status": "PASSED",
  "scenario": {
    "name": "MIDNIGHT_00_06",
    "durationSeconds": 30.0,
    "steps": 36,
    "virtualStartTime": "2026-09-15T00:00:00+08:00",
    "virtualEndTime": "2026-09-15T06:00:00+08:00"
  },
  "checks": {
    "stateReceived": true,
    "autoSleepEventSent": true,
    "observedSleeping": true,
    "observedSleepDepths": ["Deep", "Shallow"],
    "finalSleeping": false
  },
  "finalDemands": {},
  "finalSleep": {}
}
```

`finalDemands` 和 `finalSleep` 直接复制最后一条 `/internal_need/state` 中对应对象。
