# 性格规则

## 参数和预设

四个性格参数均为整数 0..100：A 亲人度、O 服从性、E 活泼度、C 胆量。

| 预设 | A | O | E | C |
|---|---:|---:|---:|---:|
| `Custom` 默认 | 50 | 50 | 50 | 50 |
| `GentleCompanion` | 85 | 75 | 30 | 40 |
| `SunnyExplorer` | 90 | 80 | 95 | 70 |
| `LoyalGuardian` | 70 | 90 | 70 | 90 |
| `ProudIndependent` | 40 | 30 | 60 | 80 |

支持预设英文值、枚举名，以及中文别名：温柔陪伴者、阳光探险家、忠诚护卫者、傲娇独立者、自定义。

## 系数公式

```text
k_joy     = (A / 50) × 0.8 + (E / 50) × 0.2
k_excite  = (A / 50) × 0.3 + (E / 50) × 0.7
k_anxiety = (1.5 - C / 100) × (A / 50)
k_fear    = 2.0 - C / 50
k_curious = (E / 50) × (1.0 + 0.3 × (1.0 - C / 100))
k_calm    = (O + A) / 100
k_social  = k_joy
```

输出话题中的系数按 4 位小数舍入。

## 生效范围

| 场景 | 是否使用性格系数 |
|---|---|
| 50 个感知情绪事件 | 是，每个情绪增量乘各自系数 |
| 行为结果随机情绪变化 | 否 |
| 情绪自然衰减 | 否 |
| Social 晨起初始化 | 是，随机基础值乘 `k_social` |
| Exploration 晨起初始化 | 是，随机基础值乘 `k_curious` |
| 需求自然增长或动作恢复 | 否 |

改变性格只影响后续计算，不追溯修改当前需求或情绪。若当天晨起初始化已经完成，之后修改性格不会立即重算 Social/Exploration。

## ROS2 参数规则

`personality_node` 暴露动态参数：`profile`、`A`、`O`、`E`、`C`。

- 只写 `profile=<正式预设>`：自动把四个参数替换成预设值。
- 写任意 A/O/E/C：profile 自动切换为 `Custom`，未写的其余参数保持原值。
- 同一次参数请求不能同时设置非 Custom 预设和自定义 A/O/E/C。
- 值必须是非布尔整数 0..100；非法请求整体拒绝。
- 接受后立即发布 `/personality/state`，并在最多约 0.2 秒内把 ROS 参数同步成最终状态。

`/personality/state` 使用 Reliable + Transient Local，晚启动的需求和情绪节点能收到最新状态。接收端忽略消息中的 `coefficients`，按 `params` 自行重算。

## 直接核心 API 规则

- 设置完整自定义参数时必须一次提供 A/O/E/C 四项。
- 设置单项参数会切换成 Custom。
- 设置 `Custom` 预设名本身不会把参数恢复成 50，只改变 profile 名称。
- 同步完整状态时，非 Custom profile 与 params 只分别校验合法性；代码不会验证 params 是否真的等于该预设配置。
