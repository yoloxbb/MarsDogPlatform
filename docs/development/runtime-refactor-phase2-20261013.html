1 · 持续时间与业务时间分开

范围现在的决策依据兼容边界
行为超时Blackboard 在启动时记录单调时钟，超时按实际经过时间判断。超时仍只请求取消；等待真实终态，不提前释放执行占用。
行为冷却set_cooldown 同时记录单调截止时间；后续系统时间调整不改变冷却长度。cooldown_until 保留原来的日历时间供诊断。旧调用方直接写入该字典时，在首次读取时换算一次。
候选 TTL入池时保留 created_at 的既有年龄，转换为单调截止时间；清理、去重和选择共用它。created_at 字段及排序保持不变。非正 TTL 保持原语义；过期不释放已经派发行为的占用。

测试注入两套可控时钟，覆盖系统时间前跳、回拨、过期后重新入队、重复候选 ID 和在途占用。单调时间保存在本地附属状态中，不混入事件或 ROS 消息。

范围限于 BT 超时、冷却、候选 TTL，以及语音协调器的可注入时钟。没有改造全部情绪衰减或模拟执行器计时，也没有解决跨进程时钟同步。候选入池之前的时间偏差仍沿用既有 created_at 语义。

2 · 循环动作的失败和取消正确向上返回

修正 StageExecutor._execute_loop 忽略单元结果并无条件标记完成的问题。当前模板没有启用 loop_random；本批修复该已存在的可配置分支。

发生的情况阶段处理完成记录
必需阶段没有可选单元或单元失败返回失败，交给现有 ResultEvaluator 处理。不加入 completed_stages。
可选阶段失败 / failure_policy=skip_stage按既有布尔接口允许跳过，并结束本阶段循环。不伪造阶段完成。
开始前、单元结束或间隔等待时取消返回取消原因和失败的阶段结果；取消不能被可选策略变成成功。不加入 completed_stages。
全部循环成功 / 原来允许的零次循环保留原有成功语义。仅正常完成时记录。

循环间隔改为最多 50 ms 一段的可取消等待。这个数字是软件轮询间隔，不代表底盘物理停车时延。未新增运动协议、StageOutcome 枚举、重试算法或物理停止证明。

3 · 语音交互策略从节点中拆出

原来的函数依赖完整节点及大量私有属性。现在由独立协调器接收明确的状态和能力端口；节点适配层负责连接现有客户端，旧的 12 个函数入口继续转发。

组件负责什么不再承担什么
voice_engagement.py保留旧函数签名，委托给协调器。不包含场景判断。
voice_engagement_adapter.py将节点持有的 session、generation 和现有客户端映射为状态及端口。不决定身份、目标、靠近和等待策略。
voice_engagement_coordinator.py处理 hold、身份等待、目标获取、靠近候选、会话关闭和迟到回调。不接收 ROS 节点，不访问节点私有属性。

已有场景流转：唤醒与转向 → 身份确认 → 获取视觉目标 → 构造靠近候选 → 候选池与运行时仲裁 → Action 执行 → 原有结果回调与会话等待。

协调器通过八组能力交互：会话租约、目标查询、候选池、交互执行取消、情绪延后、注意力发布、靠近候选构造、日志。仲裁和 Goal 生命周期继续由现有运行时持有。

中断与迟到：关闭当前会话只清理相应候选和待处理交互，并请求取消该交互正在执行的行为；迟到目标不能推动已替换的会话。旧 hold 迟到成功时释放捕获的 token，避免旧租约滞留。

新增纯组件测试覆盖主人链路、陌生人等待、查询超时、会话替换、迟到 hold、身份冲突、关闭与取消。测试只用普通状态对象和端口替身，无需构建 ROS 节点。

当前会话的权威状态仍由原节点持有，适配层保持这一点；本批不是全系统单一事件循环迁移。三类靠近接口仍按此前设计区分，本批不新增模式路由或导航几何转换。
