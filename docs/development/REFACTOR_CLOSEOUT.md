# 应用重构收尾与开发入口

当前修改以板端 `c21c3bf` 和前六批未提交源码为基础，保留所有既有工作。
本轮不重启生产服务、不修改设备协议、不升级锁文件或模型。
验证结果以 `out/refactor-completion-20261013/` 的日志、JUnit、安装来源及补丁哈希为准。

## 新功能应该改哪里

| 工作 | 唯一入口及约束 |
| --- | --- |
| 视觉/听觉/触觉事件 | 模块拥有事件事实；逐事件声明直驱、情绪影响、双路或仅观测 |
| 情绪与需求 | Emotion/Needs 持有权威；直接候选不因复用表达模板获得需求结算资格 |
| 候选与场景 | Behavior 的 mapper/候选池/仲裁；主等级与子等级是整数元组 |
| 语音识别流程 | speech_pipeline + SpeechRuntime；provider、会话状态、发布、时钟、ID 显式注入 |
| 执行流程 | goal_execution + ExecutionRuntime；状态、资源、反馈、租约接口显式注入 |
| 行为与动作 | 原模板加表达预设；不增加空模板伪造成功；Stage 遵守取消和真实终态 |
| 三种靠近 | 场景显式指定 visual / local_nav / map_nav；几何定位归 Action 到定位服务边界 |
| 导航通信 | 新 NavigationTask + 旧 VoiceTask 兼容入口；同一任务存储，禁止自动换类型重试 |
| 运动所有权 | motion_ownership 的统一接收门禁；新增适配器必须加入恢复状态登记 |

State 的节点适配器只是原有状态的实时视图，不复制会话、Future、预留 Goal 或长期 Goal。
协调代码只能读取声明的 ports/state，不能拿到 Node 再随意读取私有字段。
架构回归会检查这条约束；新组件同时登记到 component_inventory，确保 wheel 和
ROS 安装中导入的是本轮真实源码。

## 16 个尚无外部实现的功能

找爸爸/妈妈、拿取/递送/取球/找玩具、三类进食、学习结果以及关怀/活动/位置/状态回答
仍按 capability_decisions 的所需依赖登记。它们属于待接入的产品能力，并非本次代码拆分
可以生成的物理能力或真实数据。缺身份绑定、目标/抓取反馈、语音播放及权威状态时，
Action 继续返回不支持，不能用姿态动作、空计划或假事实表示完成。

接入这些能力时由所属五人角色负责：定义输入身份和有效期、成功所需证据、失败、
取消与停止确认；增加生产/消费测试后更新能力记录和例外。表达预设仅承诺 expression_only。

## 历史审计差异处理

完整扫描发现六份历史资产在本轮前已改变，本轮保留其字节。两份 YAML 新增精确字段审阅记录：视觉删除一块
不再使用的 slam_localization 配置；导航已有 8 处恢复门禁/地图订阅配置差异。
每条差异携带 before/after、存在性、原 Git 提交、原 SHA256 和原语义哈希。
反向还原这些字段必须恢复完整冻结语义；任何额外漂移仍失败。
另四份资产分别是视觉 dashboard、两份导航恢复 XML 和 nav.launch.py。
前者修正已确认陌生人的显示门控；XML 增加空路径和占用起点检查；launch 已有多机器人
profile、TF/里程计职责、只打印/只坐标模式及 SLAM 调参。它们用原 SHA256、原提交和
当前字节 SHA256 登记“保留既有修订”，后续任何漂移仍失败。不是声称与迁移时期行为相同。
原迁移基线没有刷新；恢复策略/配置测试证明软件实现，SLAM 精度和设备效果仍需专门验收。

## 部署前仍需外部条件

- 指定机器狗、传感器与标定：TF/深度对应、运动停止、触觉采集、故障恢复。
- 核对当前 ROS 发布者与启用 profile；应用所有权不屏蔽绕过应用直接发指令的节点。
- 为五个角色填写真实账号及备份，配置 GitHub runner/分支保护，保留真实 Actions 证据。
- 新导航入口按迁移配置启用后验收；旧入口退役必须是一次明确的兼容发布。

源码回滚使用交付包中 before 文件，先核对当前 SHA256，避免覆盖新开发；新增文件单独
列在 manifest。机器人运行状态和 overlay 切换另行部署，不能用源码回滚推断设备已停止。
